# Scripts

Maintenance scripts of the web app. Run them from the repository root; each
script's header documents its arguments. The Python generators run with the
repository's Python environment (anndata, h5py, zarr), except where a header
names a pinned one.

## Test runners

| Script | Purpose |
| --- | --- |
| `run-web-tests.mjs` | The contract suite: every `tests/*.test.mjs` (or the files named) under `node --test` (`npm test`), one process a file, as many at once as `node --test` runs, with the network guard preloaded. A file that finishes no test for 5 minutes (`CELLUCID_TEST_STALL_MS`) is stopped and fails naming the last test it finished; a slow machine still finishing tests never fails (`tests/web-test-runner-contract.test.mjs`). Each file's process leads a process group of its own, so an interrupted run (Ctrl-C, SIGTERM) stops every file it started before it ends. |
| `slow-delivery-preload.mjs` | A preload for the contract suite (`NODE_OPTIONS="--import ./scripts/slow-delivery-preload.mjs" npm test`) that delivers every `MessagePort` and `BroadcastChannel` message late (in order) and runs timers on a 16 ms tick, as a loaded Windows runner does: a test that fails under it waits a fixed time for something it should wait for the event of. |
| `network-guard-preload.mjs` | Preloaded by `run-web-tests.mjs` into every test file's process (alone: `node --import ./scripts/network-guard-preload.mjs --test tests/<file>.test.mjs`): a request to any host but this machine's loopback (`fetch`, and every TCP connection beneath it) is refused before a lookup, written to stderr with the stack that asked, and the file that made it fails at exit naming each URL, even when the code caught the refusal or asked after its test ended. A contract test fakes every host it reads; the one opt-in, for a test whose subject is a real host (none today), is `allowRealHost(t, host)` (`tests/helpers/real-network.mjs`), for that test only. |
| `run-browser-shard-bounded.mjs` | One Playwright shard in bounded browser processes (`npm run test:browser:bounded -- --project=<engine> --shard=k/n [--headed]`, CI): the shard's test files (each test owned by the file whose suite holds it, never the helper its `test()` call stands in), split into batches of at most so many files and tests a browser, each batch checked to select exactly its planned tests before it runs. It passes its environment on to every listing and batch, so `CELLUCID_CONTROL_WALK` (`playwright.config.mjs`) holds in all of them: CI's browser job runs 8 shards of every engine with it `apart` (the control walk left out), its `control-walk` job the walk's spec files alone with it `only`, `--project=chromium --shard=k/4`, a file a job. |
| `run-browser-specs-repeat.mjs` | Runs browser specs many times in every engine to show a race before CI does (`npm run test:browser:repeat -- [spec or helper …] [--repeat=N] [--project=<engine> …] [--grep=<pattern>]`): each engine in turn (Chromium, Firefox, WebKit), N times (5 by default), one worker, no retries, in browser processes no longer-lived than CI's (the bounded runner's files and tests a process), failing on any single failed run and printing each engine's passed and failed runs and the failing tests. Without paths it takes the specs changed relative to `origin/main` (committed, uncommitted and untracked) and every spec importing a changed helper. |
| `install-linux-engine-libraries.mjs` | CI's Linux browser jobs: installs the libraries a Playwright engine needs (`node scripts/install-linux-engine-libraries.mjs <engine>`). Playwright names the missing packages (`install-deps --dry-run`), each is fetched under a speed floor (from the next mirror of the runner's apt mirror list when a transfer falls under it), its size and hash checked, and apt installs from those files only: apt cannot leave a mirror connection that trickles, and one runner in two dozen got one. |
| `serve-browser-tests.mjs` | The static server the Playwright config starts for the browser tests. |
| `check-analytics-property.mjs` | Checks the live Google Analytics property (its tag container) against the privacy model: no automatic user-provided data collection, every data parameter of the page address redacted (enhanced measurement is on by choice and not checked). The property's settings are made in the Google Analytics admin; run this after changing them. |
| `browser-test-ports.mjs` | The loopback ports of the browser-test servers, shared by the config, the server and the specs, and the name the app is opened at (`CELLUCID_BROWSER_TEST_APP_HOST=deployed.localhost` runs the specs as a deployed site, its workers started from their bundles). |

## Inventory and design tokens

| Script | Purpose |
| --- | --- |
| `generate-web-asset-inventory.mjs` | Builds the worker bundles and the page bundle (below) first, then rewrites `cellucid-web-assets.json`, stamps the build id in `index.html`, and dates `sitemap.xml` and `.well-known/security.txt` from it; writes each shipped page's import map, the `?v=` content version of every script it names and the CSP hashes of its inline scripts; `--check` verifies all of it, bundles included, and writes nothing (see `CONTRIBUTING.md`). Needs `npm ci`. |
| `build-worker-bundles.mjs` | Used by the generator: builds each entry of `WORKER_ENTRIES` (every worker, and every module a worker imports by URL) with the pinned esbuild into `assets/workers/<name>.<sha256-12>.js` plus its source map, and writes `assets/workers/scripts.js`, which a page starts each worker from (`assets/js/workers/worker-script.js`). |
| `build-page-bundle.mjs` | Used by the generator: builds the app's module graph (`assets/js/app/main.js` and every module it imports, statically or on demand) into the few files of `assets/page/` a deployed site loads; a page served from this machine runs its sources. |
| `build-wasm-codecs.mjs` | Builds `assets/wasm/codecs.wasm` (zstd 1.5.6, lz4 1.10.0 and c-blosc 1.21.6 decoders, and the HDF5 bitshuffle filter's) and copies their licences to `assets/wasm/LICENSES/`, from the release tarballs pinned by SHA-256, with zig 0.13.0 pinned per host (`zig cc -target wasm32-freestanding`, SIMD and bulk memory, no C library: `wasm-codecs/` holds the exports, allocator and headers). Downloads are kept in `node_modules/.cache/wasm-codecs/`; `--check` rebuilds and compares byte for byte, `--offline` never fetches. Run it only to change a pinned version or the C exports, then update the digest in `tests/wasm-codecs-contract.test.mjs` and regenerate the inventory. |
| `generate-relay-bundle.mjs` | Writes `relay/generated/bundle.js`, what the agent relay Worker knows of the web app: the wire protocol shared with the tab, the action catalogue as MCP tools, the agent instructions, the Cellucid version and the page's origin. Rerun after changing an action, the instructions, the protocol or the version; `--check` writes nothing and exits 1 when it is stale (`tests/relay-bundle-contract.test.mjs`; `relay/README.md`). |
| `generate-action-reference.mjs` | Writes the developer docs' action reference (`user_guide/web_app/p_developer_docs/30_action_reference.md` in the docs tree named by `CELLUCID_PYTHON_DOCS`, else the sibling `cellucid-python/docs`; `--out <file>` writes elsewhere) from the action catalogue: every action with its parameters, the state domains it changes, its timeline label and pseudocode, and every read with what it returns. Rerun after adding or changing an action; `--check` writes nothing and exits 1 when the page is stale or missing (`tests/action-reference-contract.test.mjs`). |
| `relay-live-check.mjs` | Checks the deployed agent relay end to end without anyone's Claude or ChatGPT account: this script is the MCP client (discovery, Dynamic Client Registration, PKCE, ChatGPT's and Claude Code's client metadata documents, both protocol eras, tool calls, the view card's resource, refresh-token rotation) and a Chromium page on `http://127.0.0.1:8000` is the person's tab (approval by link and by typed code, calls reaching it after the pairing was idle, Forget). Prints PASS or FAIL per check and never a token; `--relay`, `--idle <s>`, `--out <file.json>`. Needs the network; not in CI (`relay/README.md`). |
| `generate-action-versions.mjs` | Keeps one example file for every version of every action's parameters in `tests/fixtures/action-versions/<type>@<version>.json` (the shape of that version's params schema without its words, and an example), so histories recorded with older parameters keep replaying: writes the file of each action's current version once and never changes it, removes the files of actions that are gone; `--check` writes nothing and exits 1 on a missing, stale or orphaned file. After changing an action's parameters, bump its `version`, add `upgrade[<old version>]`, and rerun (`tests/action-versions-contract.test.mjs`). |
| `generate-action-catalog.mjs` | Writes the action catalogue document (`catalogDocument` of every action definition, canonical JSON) to `tests/fixtures/action-catalog.json` and, byte for byte, to cellucid-python's `src/cellucid/action_catalog.json` and cellucid-r's `inst/action_catalog.json` (found beside this checkout, or where `CELLUCID_PYTHON_ROOT` and `CELLUCID_R_ROOT` say), and prints its SHA-256; `--check` writes nothing and exits 1 when one is stale. Rerun after changing an action, then regenerate the packages' methods (`python scripts/generate_actions.py` in cellucid-python, `Rscript tools/generate-actions.R` in cellucid-r) and pin the digest in `tests/action-catalog-document-contract.test.mjs`, cellucid-python's `tests/test_action_catalog.py` and cellucid-r's `tests/testthat/test-actions.R`. |
| `generate-history-golden.mjs` | Writes the golden history every reader is held to: `tests/fixtures/history-golden.cellucid-session` (a format-4 file in the History v2 shape holding every kind of record of `app/history/model.js`: trackers, branches, a group, squashed and paused records, turns, notes, the journal, each step's parameters version) and `history-golden.expected.json` (its reading, diffs, stale results, methods, pseudocode and apply plans), and the same two files into cellucid-python's `tests/fixtures/history_golden/` and cellucid-r's `tests/testthat/fixtures/history_golden/` (beside this checkout, or where `CELLUCID_PYTHON_ROOT` and `CELLUCID_R_ROOT` say); prints both SHA-256s to pin in `tests/history-golden-fixture.test.mjs` and the packages' session tests. `--check` compares content (inflated chunks), not gzip bytes. |
| `generate-history-model.mjs` | Writes the history model (`historyModelDocument` of `assets/js/app/history/model.js`: every record a history, a saved state and a session file hold, as a JSON Schema, canonical JSON) to `tests/fixtures/history-model.schema.json` and, byte for byte, to cellucid-python's `src/cellucid/history_model.schema.json` and cellucid-r's `inst/history_model.schema.json` (found as for the action catalogue), and prints its SHA-256; `--check` writes nothing and exits 1 when one is stale. Rerun after changing a record, then pin the digest in `tests/history-model-schema.test.mjs` and the two packages' session reader tests. |
| `validate-tokens.js` | Every design-token `var(--...)` resolves to a defined custom property. |
| `validate-token-types.js` | `types/design-tokens.d.ts` agrees with the token definitions. |

## Benchmarks

Nothing they produce is committed. Every one that starts a browser launches it
through `lib/browser-launch.mjs`: on the machine's GPU (Chromium on Metal
through ANGLE on macOS), with the WebGL renderer recorded in its results, and
refusing a software renderer (SwiftShader, llvmpipe), on which a frame of
millions of points is CPU work and no timing is the app's, unless the run
passes `--software-gl`.

| Script | Measures |
| --- | --- |
| `benchmark-analysis.mjs` | Marker genes and differential expression on a real dataset in Chromium, over an unshaped and a shaped link (`npm run bench:analysis`). |
| `benchmark-anndata.mjs` (+ `benchmark-anndata/`) | The AnnData reader (and, with `--baseline`, an earlier revision's), on generated or given files, locally and over a simulated link (`npm run bench:anndata`). |
| `benchmark-formats.mjs` (+ `benchmark-formats/`) | Every non-AnnData format the browser reads (Loom, Cell Ranger `outs/`, MatrixMarket, Seurat and SingleCellExperiment `.rds`/`.rda`, `.h5mu`, MuData Zarr) against the same data as a Cellucid-ready `.h5ad`, on generated (`generate.py`, `generate.R`) or given files: first view, first gene, peak memory, and a stream format's pass against plain inflate (`npm run bench:formats`). |
| `benchmark-hdf5-reader.mjs` | The HDF5 reader against h5wasm (`npm run bench:hdf5`). |
| `history-stress.mjs` (+ `tests/stress/`) | The action history at scale (`npm run stress:history`): mixed histories of 1k to 100k steps on a synthetic 1M-cell, 20 000-gene page (camera, colours, filters, highlight brushes of 1k, 500k and ~1M cells, label edits, user fields, settings, layout, differential-expression, marker and correlation results; 100 branches, 10 trackers), driving the real dispatcher, history, value pool, session file and autosave: recording overhead per step kind, the memory accounting, jump, undo, redo, delete-a-step and replay, autosave write time and IndexedDB bytes, JS heap, session file size (by chunk) and load time, `history.get` size against the connector's 150k-character limit; each step kind alone (bytes per step); `--readers` times cellucid-python's and cellucid-r's session readers. The browser half is `tests/browser/history-stress.spec.mjs` (`CELLUCID_HISTORY_STRESS=1`). Results: `tests/stress/RESULTS.md`. |
| `benchmark-anndata-copy.mjs` | The copy of a dataset as a Cellucid-ready AnnData `.zarr.zip` (`assets/js/data/anndata/write/copy.js`) from any file or folder the app reads, to a file: time, write rate, peak memory; `--cell-major` makes the copy transpose X in passes (`--budget-mb`), `--workers N` encodes on N decode workers as the reader worker does, `--verify` compares the copy with the source. |
| `efficiency-floor.mjs` (+ `efficiency-floor/`) | Every element the viewer reads (obs of each kind, embeddings, vector fields, graphs, X as CSR, CSC and dense, layers, raw, var, uns, stored outlier quantiles, MuData modalities), in every storage (`.h5ad` gzip/lzf/unfiltered/contiguous, Zarr v2/v3 folders and ZIPs, Zarr v3 sharded (CSR, CSC and dense X; folder and ZIP), Cellucid-ready priority files, the stores `cellucid_serve` and `serve_anndata` answer (cellucid-r from its sources, cellucid-python's `PriorityStore`), `.h5mu`, MuData Zarr, Loom, Cell Ranger `outs/`), at every share and subsampling method, over a throttled link, from a picked file, or as a copy kept in this browser (`--plan kept`: a whole download read through its page checksums): bytes, requests and time against the floor computed from the file's own layout (time: a response's first byte a round trip after it is asked, dependent steps one after another; each element, and each step that reads what an earlier one read first, judged) (uncompressed chunks, as served stores hold them, priced by the bytes a read needs; `generate.py` writes the corpus, `layout.py` each file's chunk map with h5py/zarr-python, `codecs.mjs` the decoding throughput of each codec in Node, `cpu-browser.mjs` in Chromium, Firefox and WebKit, against `DecompressionStream`, other decoders and every core). Scale stores (`scale.py`, streamed, up to hundreds of millions of cells; `scale-run.mjs`) check that a 10 % share costs about a tenth on every axis. `--plan served` serves a dataset on this machine with cellucid-python's and cellucid-r's servers (`served.py`, `served.R`: a synthetic object of any size, or a file) and reads it over loopback: each server's time before its first answer and each step's time, bytes and requests. `app-run.mjs` runs the whole app in one engine (Chromium, Firefox or WebKit) on a picked file or folder, a server on loopback or a link: first picture (and the requests before it), every cell, genes, a differential-expression read, peak memory. `tests/efficiency-floor.test.mjs` holds the floor in CI. |
| `benchmark-real-links.mjs` | The whole app opening datasets in Chromium: real links from real hosts, files served over a simulated HTTP/1.1 or HTTP/2 link, or files of this computer picked with File… and Folder…, with each step's bytes, requests, peak memory and main-thread long tasks (and, for a progressive opening, its first view's cells and the time until every cell asked for is open); optionally against an earlier revision. `--query "&cells=1%25"` opens each link with a subsample; `--open-only` stops once it is open. `--corpus efficiency-floor/public-links.json` (with `--ids`, `--with-heavy`) takes the real-link corpus, each link at the default Cells to open and at the shares it names, and records the time to the first picture; with `--again`, every request the later visit sent; `--linger-s N` keeps each page open N seconds after its last step (0, the default, closes it at once: what a page read is kept as it arrives); `--genes N` shows the first N genes one after another (the first gene, then later ones). |
| `efficiency-floor/public-links.mjs` (+ `public-links.json`) | Real public links of every source and format (CELLxGENE, Zenodo, GEO incl. `.h5ad.gz`, 10x, MatrixMarket, `.rds.gz` and text matrices, EBI Single Cell Expression Atlas, Figshare, Hugging Face, GitHub, Dropbox, Google Drive, public S3, the sample catalog) opened by the app's own path in Node over the real network, one process per link, a browser's six connections to an HTTP/1.1 host: each step's time, bytes, requests and share of the file, the host's behaviour (HTTP version, ranges, CORS and exposed headers, content coding, validators, rate limits), a second visit over the same browser storage and every request it sent (`PUBLIC_LINKS_TRACE=1`: every request of every step, timed). `--report` writes the link × step table. No browser: it runs where the heavy-job queue is busy. |
| `render-scenarios.mjs` | Render and interaction scenarios through the render probes: frames, passes and, with `--timing`, GPU time. |
