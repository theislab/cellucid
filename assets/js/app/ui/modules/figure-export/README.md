## Figure Export module

This folder implements **publication-grade SVG/PNG export** for Cellucid without touching the main render loop.

### Design goals

- **Exact request semantics**: export format and SVG representation are never inferred, changed, retried, or substituted.
- **Exactly as framed on screen**: a plot takes its view's aspect — the pane's viewport, or the framing crop's — as the largest rectangle of that aspect inside the requested size, and the view fills it with the screen's own projection: no letterbox, no blank band, points at their on-screen size. The axes are the rulers of exactly what is drawn (`utils/plot-fit.js`).
- **View fidelity**: camera, filters, colors, framing, the reference layer (grid box or studio backdrop), and atmospheric fog come from the current view; PNG and Hybrid preserve the shader-rendered point pass, while vector strategies preserve their explicitly documented circle representation.
- **Performance-safe**: heavy work runs only on explicit preview/export actions, and an export's per-cell passes and encodes run in the export worker, so the page's main thread stays responsive. The one exception is a browser whose workers have no WebGL2 (WebKitGTK and WPE, [WebKit bug 209809](https://bugs.webkit.org/show_bug.cgi?id=209809); Safari 16.4–16.6, and 17.0–17.1 on macOS Ventura, [WebKit bug 183720](https://bugs.webkit.org/show_bug.cgi?id=183720)): there the point pass is drawn on the page, by the same handler.
- **DRY + extensible**: shared layout/components are reused across SVG + PNG.

### Main pieces

- `index.js`: module entry point (wires UI + engine).
- `figure-export-ui.js`: sidebar panel (collects user inputs + triggers export/preview).
- `figure-export-engine.js`: snapshots current view buffers + orchestrates rendering/download/notifications.
- `utils/figure-export-worker.js` + `utils/figure-export-worker-client.js`: the export's worker. Every per-cell pass and every encode runs there, never on the page's main thread: whether a figure draws any cell (`drawnCells`), the shader-accurate point pass (on OffscreenCanvas WebGL2 contexts the worker keeps while it lives, one per antialiasing setting; with no session open the worker and the page's drawing host end after 10 s idle, `workers/idle-retirement.js`, and start again for the next export), the vector point markup, and PNG encoding with `OffscreenCanvas.convertToBlob` plus the `iTXt` metadata. Each rendered file opens a session: a typed array is copied to the worker once per session however many passes read it, and closing the session releases it. Before the first point pass the worker is asked once whether it can create a WebGL2 context (`webgl2`); where it cannot, the same handler (`createFigureExportWorkerHandler`) runs on the page for the point passes only (`spriteZoomLimit`, `rasterizePoints`, and `rasterContext`, which describes the context they draw with: renderer, granted attributes, samples), and every other operation stays in the worker. The answer holds for the page's lifetime; `setFigureExportWorkerWebgl2(false)` states it for tests. A request outliving its export's abort rejects at once; the worker's late answer is discarded (a frame closed). Node contract tests run the same handler in-process (`tests/helpers/figure-export-worker-in-process.mjs`).
  - Includes optional **framing crop** (photography-style overlay) so users can export a chosen sub-region of the current view without changing the camera.
  - The plot takes the crop's aspect (as it takes the view's without one), so the crop fills the plot exactly; resizing the frame changes the exported region (zoom) without changing the camera. Lock aspect keeps the frame at the requested size's aspect, so the plot is then the whole requested box.

### Renderers

- `renderers/svg-renderer.js`: SVG generator (no DOM). The page writes the annotations as strings; the worker writes the points (`renderers/svg-point-markup.js`) and returns them as one Blob; the file is assembled from Blob parts, never joined into one string. Strategies:
  - **Full vector** (`full-vector`): every visible point is an SVG circle, exactly as requested.
  - **Optimized vector** (`optimized-vector`): density-preserving reduction to the user-entered target count, exactly as requested.
  - **Hybrid** (`hybrid`): points are embedded as a shader-rendered PNG while annotations remain vectors.
- `renderers/png-renderer.js`: HTML Canvas composer with embedded UTF-8 PNG `iTXt` metadata (`buildPngTextMetadata()` publishes the exact chunk map so it can be compared with the SVG's).
  - Points are rasterized in the worker (on the page where a worker has no WebGL2) via WebGL2 using the same shader variants as the viewer, so 3D “sphere” shading exports correctly (not as flat dots); the frame comes back as an ImageBitmap and is copied one to one onto the plot's device pixels.
  - The composed canvas crosses to the worker as its pixels (`getImageData`, read in bands of rows with a yield between them so no read is a long task; `pagePixelsInBands` in `utils/figure-export-worker-client.js`) and is encoded there with `OffscreenCanvas.convertToBlob`, the encoder `toBlob` uses. Every image the page hands the worker to encode (the composed figure, a backdrop look's raster, a Hybrid point pass) crosses as pixels, never as an ImageBitmap of a page canvas: on Linux WebKit (WPE), whose workers have no GL, such a bitmap reached the encoder without the canvas's pixels.
- `renderers/svg-point-markup.js`: the `<circle>` markup of Full Vector and Optimized Vector, encoded in the worker straight into a reused 1 MiB buffer whose contents become Blob parts, so memory is the file plus one buffer, and the markup is never a string.

### Components (shared building blocks)

- `components/axes-builder.js`: the axes, rulers of what the plot shows, drawn only where they are rulers (`figureViewHasAxes()`, `figurePanelAxes()`): a 1-D or 2-D view in planar navigation, looked at straight down its plane, every cell on it. A 3-D view (any navigation) or an orbited flat view is a perspective picture of cells at many depths, where one plot length is a different distance at every depth: it has no axes and no axis margins, and the orientation widget shows its directions (found 2026-11-11, F86: camera-space ticks on the focal plane were read as UMAP coordinates). `computeSourceAxisBounds()` gives the embedding coordinates the view's (or crop's) edges show on the embedding's plane, so the axes frame exactly what is drawn. `planAxisTicks()` keeps the nice ticks that lie between the ends, each at its own value's place, at the finest nice step (1, 2, 2.5, 4 or 5 × 10ⁿ) whose labels, measured with the figure's font (`utils/text-measure.js`), keep half an em apart — at most five, fewer as the axis gets shorter, and one where two cannot fit; exact user-entered axis labels. A plot with no visible cell draws the "No visible cells" notice instead of axes.
  - `planFigureAxes()` lays a plot's axes out once, for the plot's size: every axis line, tick, tick label and axis label, and the margins they need on each side of the plot (`margins`). The tick labels are measured (the layout's measurement); the y tick labels stand a gap left of their ticks, centered on them at any size; the y-axis label stands past the widest y tick label, the x-axis label under the x tick labels; a tick label at a plot's corner, or an axis label longer than its side, is reserved on that side too; an axis label longer than its side starts at the plot's shared corner and runs on past the far end, and the x tick labels stand under a y tick label that one of them reaches under, so nothing overlaps at any text size (1–500 px). The layout plans the axes (`layout.axes`, `pane.axes`) and `renderSvgAxes()` / `drawCanvasAxes()` draw exactly that plan, placed on the plot (`placeFigureAxes()`, which refuses a plot of another size): neither measures or places anything, so the PNG and the SVG cannot differ (found 2026-11-11, F158 / L24-6: the y label stood a fixed `5 + 8 + 1.15 × label` px left of the axis, so at 17 px ticks and a 20 px label "UMAP 2" ran into "-0.5"; the margins were a fixed 62 px at any text size; and the PNG wrote the y tick labels 2 px from their ticks, the SVG 8 px).
- `components/legend-builder.js`: categorical + continuous legends (sourced from `DataState.getLegendModel()` for color consistency).
  - A category entry's swatch and label are centered on its row, the label on an alphabetic baseline half a capital below the center (`entryPlacement()`), in both builders (L6-2: the SVG used an ideographic baseline at the swatch's bottom and the PNG an alphabetic one, and a large legend font lifted the first label into the title). A filled swatch has one outline in both formats (`SWATCH_OUTLINE`, 0.5 px; the SVG wrote 0.25).
  - Highlighted cells: a figure draws the active highlight page's cells over the coloring in the highlight's color (`HIGHLIGHT_COLOR` in `rendering/shaders/high-perf-shaders.js`, the one color the viewer, the point raster and the vector points draw them in, each dot inside a black ring, `highlightRingColorFor`, at the shader's radii, `highlightRingRadii`; F162: a dot alone vanished among cells colored like it), so wherever it draws them its legend carries an entry for them: a swatch of that color and `Highlighted: <page> (<N> cells)`, the page's name and its highlighted cell count (`utils/highlight-legend.js`; F158: a reader of the figure took the cyan highlight of the germ cells over a gene's viridis for the gene). `planLegend({ highlight })` plans it as one more row under the entries, the color bar or the title, and the layout sizes the legend with it; a panel colored by no field gets a legend of the highlight alone. The entry follows the legend (Legend off, no entry) and the cells drawn: a panel that draws none of them (filtered out, or not admitted by the level of detail) carries none. In a grid the shared legend carries it when any panel draws highlighted cells, else each such panel's own legend; when no panel is colored by a field, one shared legend lists the highlight.
  - `planLegend()` plans a legend once: each entry's whole text (with its `(hidden)` marker), its columns — each as wide as the longest entry — its rows, and the box it needs; a color bar's end labels and its scale note wrapped to the bar. `renderSvgLegend()` and `drawCanvasLegend()` draw that plan inside the rectangle the layout reserved for it and measure nothing, so the two formats write the same text in the same columns and no label is cut.
  - `legendEntries()` lists the categories with cells after the filters on other fields (`model.counts.available`), in the model's order; a category those filters leave no cell is not listed (the figure has none of it; the title, or a grid panel's label, names the filter). Categories the person hid (`model.visible[i] === 0`: one byte per category, `utils/category-state.js`) keep their entry but lose their color: the swatch becomes a hollow gray outline and the label is marked `(hidden)`. Dropping the entry would make a filtered view indistinguishable from a complete one; keeping a colored swatch would send a reader hunting the plot for points that were never drawn.
  - A logarithmic colorbar (`model.logEnabled`) is labeled `Log10 color scale` with its true midpoint (the geometric mean), because endpoint-only labels invite a linear read-off that is wrong by orders of magnitude.
  - `resolveSharedGridLegend()` decides whether one legend may stand for a whole multi-panel grid: only when every panel uses the same field **and** publishes a semantically equal legend model (including which categories are hidden). Panels that disagree each get their own legend inside their cell — a colored panel is never exported without a legend.
- `components/reference-grid.js`: the viewer's reference-grid box, reproduced as vector rules.
  - `drawGrid()` (`rendering/viewer.js`) paints six quads of half-extent `GRID_SIZE` shaded by a pure line pattern — minor rules every `gridSpacing`, major every fifth, a frame at the box edges, origin-axis rules — with **no fog term**. Straight 3D lines project to straight 2D lines, so the grid is emitted as `<line>` elements and Canvas2D strokes rather than a second raster layer: a full-vector SVG stays fully editable, and PNG and SVG consume one geometry model so they cannot disagree.
  - Each rule is one opaque stroke whose color is the shader's fragment color already composited at the plane's effective opacity over the figure's own paper. Opaque strokes are what make crossings correct: the shader takes `max()` across the two rule families, so a crossing must be as dark as one rule, not two.
  - A rule that belongs to several classes (minor + major + frame, or minor + major + origin) is emitted as nested concentric bands, widest first, reproducing the shader's cross-section instead of flattening it.
  - Known bounded differences: the plane-surface vignette is not drawn (≤ ~1.3/255); crossings between two planes' rules are up to ~6/255 lighter than on screen; where one class's outer band crosses another's core the last-drawn class wins. None carries a data claim.
  - `buildReferenceGridModel()` is also the entry point for the studio backdrop: a `kind: 'studio'` appearance is handed to `components/studio-backdrop-export.js`, and `renderSvgReferenceGrid(model, idPrefix)` / `drawCanvasReferenceGrid()` draw either model. The SVG id prefix names the studio backdrop's gradients, so it is unique per panel.
- `components/studio-backdrop-export.js`: the viewer's studio backdrop (`Studio (light)`, `Studio (dark)`), reproduced as vectors from the same functions and constants the shader is generated from (`rendering/studio-backdrop.js`).
  - The pane geometry the viewer drew with travels in the export render state (`renderState.backdrop`: floor height, whether the embedding is flat, data center and extents, glow center, device pixel ratio, settled surface), so the export never re-derives it. Which surfaces are drawn, and where the dot surface stands (square to the camera behind the data for a level 3-D view), come from the same `resolveStudioSurfaceWeights` and `resolveStudioBackdropPlane` the viewer calls.
  - Floor rules are `<line>`s stroked with a linear gradient sampled at 24 points along each rule, because the shader's strength varies along a rule (stage fade, grazing fade, lattice family weight). Dots are circles, round on screen as in the shader. The glow and the pool under the data are radial gradients under an affine `gradientTransform` — exactly the pane-space ellipses the shader draws. Lattice families are enumerated only where they can be visible — near the screen samples where each shows, so a flat pane's dot plane seen at a grazing angle costs what is on screen, with no ceiling on how far the plane runs — and marks fainter than half a code value are omitted.
  - Rules and dots are opaque, composited onto the surface, glow and pool beneath them, so crossings match the shader's `max()`. The glow lightens the viewer's own surface and is drawn only when the figure's paper is exactly that color; the pool is ink at a varying opacity and is exact over any paper.
  - Known bounded differences: linear interpolation between a rule's 24 gradient stops (far below one code value); a rule's width is taken where it is strongest (the shader widens a rule by at most a quarter CSS pixel as it turns major); the screen's sub-code-value dither is not reproduced; the 0.3 s surface crossfade after a dimension or navigation change is exported at its settled end. None carries a data claim.
- `components/backdrop-look-export.js`: the viewer's backdrop looks (`Atelier`, `Nebula`, `Abyss`, `Aurora`, light and dark; `rendering/backdrops/`), which are procedural rasters and cannot become vectors.
  - Each pane's look travels frozen in the export render state (`renderState.backdrop.look`: the look id, the data tints, the ambient clock and, for Atelier, the baked contact-shadow map), and `rendering/backdrops/backdrop-look-raster.js` draws it again with the same renderer and shaders in a private WebGL2 context kept for the page. The sky bakes are deterministic, so they are re-baked there and match the screen.
  - Each raster pixel maps to the pane NDC it shows through the points' own viewport-to-plot placement (`resolveBackdropLookPlacement()`, from `createPlotPlacement()`), so the look stays registered with the points, under a crop too. The pixel density is the figure's: star cores, grain and motes keep their on-screen size in CSS pixels.
  - PNG draws the raster at device pixels under the points; SVG embeds it as one `<image class="cellucid-backdrop-look">` at the hybrid point raster's 2× density. A look is drawn only on the viewer's own paper (`Background: Match viewer`). The export preview shows the last raster rendered for the same state and redraws when a new one lands.
  - Known bounded differences: the sub-code-value dither is re-drawn, not copied; a figure larger than the GPU's largest render target is drawn at that size and scaled up; the 0.35 s fade after choosing a look is exported settled.
- `components/orientation-indicator.js`: 3D orientation widget (axis triad + angles), laid out in the pane's viewport pixels and drawn scaled by the plot's pixels per viewport pixel (`plotScale`, from `createPlotPlacement()`), as the points are, so it takes the same share of every plot. The other text inside a plot — centroid labels, the `n = N selected` badge, "No visible cells" — is the figure's typography, at the sizes chosen in the Style group, and is not scaled.
- `components/centroid-overlay.js`: centroid points + centroid text overlay (WYSIWYG with viewer state).
- `components/vector-field-figure.js`: the vector field the overlay shows, as a figure draws it — a still picture of the flow, arrows on a grid as scVelo's `velocity_embedding_grid`: the cells the view shows with a vector, through its camera onto the plot; per node of a 40-across grid the Gaussian-weighted mean (σ = half a step) over max(1, weight), nodes under 1% of the 99th-percentile weight dropped, arrows scaled by their mean length to half a step (matplotlib's quiver autoscale, as scVelo); colored by mean speed over the field's largest through the overlay's color scheme, outlined in the paper's color; a key in the plot's bottom-right corner (field, how it is drawn, speed range in the embedding's units). One plan (`planVectorFieldFigure`) is drawn by SVG, PNG and the preview. The engine reads the arrays (`readFigureVectorFields`: the shown field and color scheme from the controls, `overlay-fidelity.js`; the vectors from the vector-field manager) before the synchronous snapshot, and the provenance names the field per panel.
- `components/fidelity-warning-dialog.js`: blocks an export before rendering when the requested representation cannot reproduce the active view.
  - Current blockers: missing WebGL2/camera matrices for shader-accurate rasterization, an enabled connectivity overlay, any render mode other than Points, and an unreadable render-mode, background, or velocity control. The velocity vector field does not block: it is drawn (below).
  - Blockers are for **data layers** only. Interaction chrome — the orbit compass, lasso and selection-radius indicators, multiview title chips, the projectile sandbox — is never exported and never blocks; the Annotations block states it up front instead, because blocking on always-on chrome would make ordinary exports impossible.

### Utilities

- `utils/layout.js`: every rectangle of a figure, for the SVG and PNG renderers and the preview alike. A legend is as large as its entries need (its plan comes from `planLegend()`), and the figure grows around it: nothing caps a legend at the plot's size and no entry is ever shortened.
  - `computeFigureLayout(payload)`: an export payload's layout, which both renderers call, so the PNG and the SVG of one export are laid out by one call: each panel's axes (`figurePanelAxes()`, with the bounds `computeSourceAxisBounds()` gives and the payload's axis labels and fonts), each legend, and the highlight's legend entry (`figureHighlightLegend()`), for `computeSingleViewLayout()` or `computeGridFigureLayout()`. The export preview lays its single view out with the same functions.
  - `computeSingleViewLayout()`: the requested size is the plot's bounding box; the plot is the largest rectangle of its view's aspect (`plotAspect`) inside it, and axes (when the view has them, `axes`), title and legend are added around that fitted plot, so the figure has no blank band. The axis margins are what the plot's axes need (`planFigureAxes()`), at least `PLOT_PADDING` (10 px) on every side. A legend beside the plot fills the plot's height in as many columns as its entries take and is at least 240 px wide (`LEGEND_MIN_WIDTH_BESIDE`, a color bar's length); a legend below fills the plot's width in as many rows as they take, below the x-axis margin. Its box is what its entries need. A title wider than the figure widens it.
  - `computeGridFigureLayout()`: the whole multi-panel figure, a composed figure, which both renderers call (no renderer keeps grid geometry of its own). Every panel's plot has one height and its own view's aspect (`plotAspects`); columns and rows are as large as their panels need, with axis margins only for a column or row where a panel draws axes (`panelAxes`: what each panel's axes show, or null), each as large as its panels' axes need at the plot height tried (`planFigureAxes()`; a row's top margin too, so a tick label at a plot's top corner stays under the panel's title), so the plots of a row start at one y and those of a column at one x (`composeGrid()`). The requested size is the box the figure fits: the plot height is the largest whole number whose composition — plots, margins, labels, legends, title — fits it (found by halving), and the figure is exactly that composition, never padded out to the box (found 2026-11-11, F86: a figure of two tall views was the full requested size with narrow strips in its corner, of different heights because each legend took its width out of a cell before the plot was fitted). Legends take room from the plots down to `PANEL_LEGEND_SHARE` (0.5) of the height they have without legends and never below 80 × 64 px (`PANEL_PLOT_MIN_WIDTH` × `PANEL_PLOT_MIN_HEIGHT`); past that the figure grows. Panels that agree share one legend beside the grid (its top level with the first row's plots) or below it, sized to its entries. Panels that disagree each carry their own: beside its plot (Legend: Right), unless beside the plot the grid has without legends it would be wider than that plot; then, and for Legend: Bottom, below it at its column's width. When that arrangement does not keep to the box, every legend beside and then every legend below is tried, and the first that keeps to it is drawn (`arrangementOf`; else the one reaching least past it): decided on the legend-free plot alone, a legend kept beside a plot the legends then shrank was planned again in more columns, and two wide views in 800 × 600 came out as 182 × 114 strips in a 1550 px figure (F113). A legend's box is its plan's, not stretched to the plot (single view too). Every rectangle is disjoint from every other: a legend never covers a plot, its axes or a panel label. A panel's title (`panelTitle` in `utils/panel-label.js`: its letter and its view's name, which both renderers draw) is measured by the composition and widens its column where it is wider than the column's plot and legend, so the plots shrink to keep the figure in the box instead of the title being cut at the panel's edge (found 2026-11-11, L24-2: "C. Neurog3 (endocrine pro" at 24 px in three columns).
- `utils/text-measure.js`: the one text measurement legends and axes are laid out with — the canvas's `measureText` for the figure's font (an `OffscreenCanvas` context), or, where there is no canvas (Node tests), a conservative per-character estimate that is never narrower than real glyphs. The layout plans with it and the builders draw the plan without measuring, so a legend box is never narrower than its text.
- `utils/figure-canvas.js`: the canvas a PNG is composed on, or a refusal. The browser's canvas limit (a side length and an area each engine sets, lower on a machine short of memory) is the only limit on a figure's size, and no engine reports it, so the canvas is allocated at the figure's device-pixel size and a pixel drawn in its far corner is read back. Where it is missing the export is refused before anything is rendered, in one sentence: `The legend of N categories needs a W×H px figure, more than this browser can draw; turn the legend off or show fewer categories.` when the figure without its legends would fit (asked of the browser the same way), otherwise `This figure is W×H px, more than this browser can draw; choose a smaller size or a lower DPI.` The SVG is written as text and has no such limit.
- `utils/panel-label.js`: the panel letters (`A`, …, `Z`, `AA`, …) shared by the drawn label and the embedded provenance, so a metadata record always names the panel it describes.
- `utils/figure-provenance.js`: the provenance record embedded into both formats. It describes **every** exported panel (`meta.views`), never only the active one — a grid stamped with one panel's field and filters is a false claim about the other panels. SVG `dc:description` and PNG `Description` come from this one builder, so the two formats of an export say the same thing.
- `utils/selection-badge.js`: the `n = N selected` badge. Single-view exports take N from DataState; each grid panel counts its own snapshot (highlighted, alpha-visible, LOD-admitted), because panels carry different filters and the active view's count is wrong for the others. Its geometry (`buildSelectionBadge()`) and its two drawers (`renderSvgSelectionBadge()`, `drawCanvasSelectionBadge()`) are shared by the SVG, the PNG and the export preview (F158: the SVG drew rounded corners the PNG did not, and the preview computed its own rectangle).
- `utils/highlight-legend.js`: the legend entry for the highlighted cells a figure draws (`highlightLegendEntry()`, `figureHighlightLegend()`: the entry and which panels draw highlighted cells, counted as the badge counts them), and the highlight's color as a figure writes it (`HIGHLIGHT_RGB`, `HIGHLIGHT_CSS`). The payload names the page (`selection.pageName`, required while cells are highlighted).
- `utils/render-mode.js`: reads the active render mode from the `#render-mode` control (the UI owner of the mode; the viewer exposes no reader) and turns anything other than Points into a fidelity blocker.
- `utils/viewer-background.js`: reads the active background from the `#background-select` control — the same pattern, because `viewer.setBackground()` derives every layer scalar from that one enum (`rendering/viewer-backgrounds.js`) and exposes no reader — and publishes the exact reference-layer appearance: the grid scalars for `Grid (light)` and `Grid (dark)` (`kind: 'grid'`), the viewer's own studio palette for `Studio (light)` and `Studio (dark)` (`kind: 'studio'`), and the look and its surface for the backdrop looks (`kind: 'look'`). `White` and `Black` publish none. An unreadable background is a fidelity blocker: an export that cannot tell whether the viewer draws a reference layer can neither include nor omit it honestly. `tests/figure-export-viewer-layer-fidelity.test.mjs` reads `rendering/viewer.js` and the grid shader, and `tests/studio-backdrop-contract.test.mjs` the studio shader, so neither side can drift silently.
- `utils/plot-fit.js`: the one placement every layer of a figure uses. `figureSourceRect()` / `figureSourceAspect()` (the view, or the framing crop), `fitPlotSize()` (the largest rectangle of that aspect in a box, for the layout), `createPlotPlacement()` (the source filling a plot of its aspect; any other aspect is refused, so no layer can letterbox), `projectIntoSource()` (whether and where a cell is drawn), `sourceRect01()` and `planPlotRaster()` (the point raster's `viewRect01` and size, scaled only past the GPU's sprite range).
- `utils/plot-projection.js`: model space → plot space for the vector reference layers: MVP projection, exact near/far clipping, and the placement the point layer uses (`createPlotPlacement`), shared by the grid and the studio backdrop so every layer of a figure stays registered.
- `utils/overlay-fidelity.js`: the data-overlay gates (connectivity, velocity vector field) and the list of interaction chrome the dialog discloses.
- `utils/fog.js`: the viewer's Beer-Lambert atmospheric fog, reproduced for the vector strategies. The `full` shader thins every point with distance (the one fog model of `rendering/shaders/fog-shaders.js`), so it fades into whatever is behind it — the paper, in a figure — and `fogDensity` starts at 0.5 — that is the depth cue a 3D scatter reads by. PNG and Hybrid run the shader; Full Vector and Optimized Vector project in JavaScript and would otherwise emit raw colors, flattening the depth axis. The sphere-impostor lighting term has no flat-disc equivalent and is not reproduced; it applies equally to every point regardless of depth, and the strategy hint says so.
- `utils/figure-ink.js`: the ink a figure writes its annotations in. Title, ticks, axis labels, panel letters, legend text, plot frame, selection badge, and the "No visible cells" notice used to be hard-coded near-black on a near-white frame — correct on white paper and unreadable on any dark figure, including every `Background: Match viewer` export taken from `Grid (dark)` or `Black`. Ink is now derived from the figure's own background luminance, using the same gray family mirrored across the midpoint. A transparent figure keeps the light palette, matching the assumption the centroid-label halo already makes.
- `utils/point-size.js`: the point diameter the figure is drawn with. `createViewportPointDiameter()` is the shaders' sprite sizing for one point (`pointSpriteSize`, `rendering/point-sprite.js`) — `u_pointSize` mixed with its perspective size (`pointScale / eyeDepth`) by the size attenuation, clamped to 0.5 px and the pane's cap (`renderState.pointSizeMax`: 160 px within the GPU's largest point) — so Full Vector and Optimized Vector circles, every format's centroid discs and the preview draw each cell at the size the screen draws it at its depth (found 2026-11-11, L6-1: the circles took `u_pointSize` as their pixel diameter, a third to a quarter of the screen's spheres at the default attenuation 0.8, near and far alike). The raster renderers multiply `u_pointSize` by the view's per-LOD size multiplier (`scientificState.lodSizeMultiplier`, in `renderers/png-renderer.js` and `renderers/svg-renderer.js`); `scalePointDiameterToRaster()` turns that into the diameter for a raster `s` times the on-screen viewport. `u_pointSize` is a *scale* and the rendered size is linear in it, so the only faithful answer is the exact product — a one-pixel floor inflates rather than protects (a dataset of around 400,000 cells opens at a point size of 0.75 and the default export is half the viewport, so a 150-DPI PNG asks for 0.586 and a floor would draw 1). The shaders' own minimum (`POINT_SPRITE_MIN_PX`, 0.5 px) is what keeps a point visible, applied to the rendered size where it belongs; the rasterizer sets the cap times its raster scale (`exportPointSizeMax`). PNG and Hybrid SVG resolve every raster point size here, so they cannot disagree about how big a cell is.
- `utils/point-projector.js`: hot-path projection helper. A requested depth sort is an O(N) binned sort and is honored at every point count.
- `utils/density-reducer.js`: viewport-space density-preserving reduction (reservoir sampling), in the coordinates of the view or the crop.
- `utils/coordinate-mapper.js`: reverse normalization for real-coordinate axes, and `sourceHasDrawnCells()`, the worker's pass that tells a plot with cells from an empty one.
- `utils/figure-title.js`: the title a figure gets until the person writes one (`figureAutoTitle`): the dataset and the colored field, and, when some of its categories are hidden, which ones as the Filters list says it (`app/utils/category-visibility-text.js`).
- `utils/png-metadata.js`: runs in the worker; validates the encoded PNG (every chunk CRC, with the shared slicing-by-16 CRC-32 of `formats/zip/crc32.js`), writes its resolution (`pHYs`, after `IHDR`: the chosen DPI as pixels per meter, so a layout program places a 300 dpi figure at its size, not at 72 dpi) and injects UTF-8 `iTXt` chunks. The keyword set is built by `buildPngTextMetadata()` in `renderers/png-renderer.js`: `Software`, `Website`, `Creation Time`, `Dataset`, `Dataset ID`, `Color Field`, `Source File`, `Description`, `Comment`. Nothing else is written — no session identifier, no page URL, no user agent, no credential. `Source File` is whatever the data source published: a dataset URL, or, for a locally opened dataset, the directory or file **name** the browser exposes. Browsers never hand a page an absolute path, so none is embedded.
- `utils/colorblindness.js`: preview-only colorblind simulation (matrix transform).
- `utils/webgl-point-rasterizer.js`: shader-accurate point rasterization for PNG + Hybrid SVG, drawing its source (`viewRect01`: the whole viewport or the crop) over its whole canvas through the screen's projection mapped onto it in clip space, run by the worker's handler on OffscreenCanvas (in the worker, or on the page where a worker has no WebGL2: `webgl2RasterAvailable()`); a pass returns its frame with `transferToImageBitmap()` and its canvas shrinks to one pixel. Its context is created with the antialiasing the viewer is drawing with **at the moment of the export** (`viewer.getAntialiasing()`), carried through the render state. Antialiasing is a live setting that also follows the dataset, and the viewer's own control measures the difference at 18% of pixels at point size 0.75 and 32% with ultra-light square points, so a fixed `true` here — or a value read once at startup — would publish a smoother cloud than the screen ever drew.

### Performance notes

- SVG export writes strings, not DOM, and the points as Blob parts in the worker: no main-thread task formats a point or holds the whole file as one string.
- A batch ZIP checksums each entry 4 MiB at a time, one slice per task, with the shared CRC-32, and takes the entry Blobs themselves as its parts (no copy); the archive is the app's one ZIP writer's (`formats/zip/writer.js`: stored entries, fixed timestamps, ZIP64 fields where a size or offset needs them, so no batch is too large for the format).
- `utils/session-settings.js`: the panel's settings as a session records them (`exportSessionSettings()` / `importSessionSettings()` on the panel): one versioned plain object, read strictly, without derived values. A number box half-way through an edit contributes its last valid value. The same settings are the parameters of the action `figure-export.set` (`FIGURE_EXPORT_PARAMS`, snake_case by `figureExportParamsOf` / `figureExportSettingsOf`; a setting added to the record is a parameter at once, `tests/figure-export-session-settings-contract.test.mjs`): a person's change is recorded as one step by observation, from the event that made it, by one observer of the whole panel (`observeSettings` in `figure-export-ui.js`, comparing the record with the one last recorded, `changedFigureExportSettings`; a title and whether it follows the dataset, Auto text and the font sizes, travel together so a burst of typing is one step); an agent, a notebook or a replay takes the action, which applies the record whole through `importSessionSettings` and refuses settings that do not go together. The panel is the settings domain's `figureExport` part (`app/state/domains/settings.js`), so undo, the history and the session file hold it.
- Every SVG export requires an explicit point strategy. Cellucid never changes Full Vector, Optimized Vector, or Hybrid based on data size, view dimension, renderer availability, or a render failure.
- Full Vector and Optimized Vector intentionally represent points as editable circles; Hybrid intentionally preserves the WebGL shader point pass. Cellucid does not override or block a valid vector choice merely because Hybrid would look closer to a shaded 3D viewport.
- PNG-only requests carry no SVG strategy. Mixed SVG + PNG requests use the explicitly selected strategy only for the SVG job.
- SVG jobs carry `dpi: null`; PNG jobs require an exact DPI. The engine never invents a PNG resolution for SVG metadata.
- Batch jobs are rendered and validated before any file is downloaded; one failed job produces no partial batch.
- Preview uses a **small downsampled sample** and debounced redraw to avoid UI jank.
